# دليلي — منصة ربط الطلاب بالمدرسين (العراق)

## فكرة المشروع
موقع متجاوب (موبايل/آيباد/لابتوب) يربط الطلاب بمدرسين موثّقين حسب المحافظة والمادة والمرحلة الدراسية.
واجهة الصفحة الرئيسية خريطة تفاعلية تعرض المدرسين، مع نظام أسئلة يوصل كإشعار لكل المدرسين المطابقين.

## الملف المرفق
`prototype/index.html` هو نموذج أولي شغّال (Frontend فقط، بيانات وهمية بالكود، بدون localStorage).
استخدمه كمرجع تصميم ومنطق واجهة — مو للنسخ الحرفي، لأنه لازم يتحول لتطبيق حقيقي مبني على Backend + قاعدة بيانات.

## الأدوار
- **طالب**: تسجيل دخول (بريد / هاتف / بدون حساب)، بروفايل فيه اسم + هاتف + محافظة + مرحلة دراسية واحدة (اختيار وحيد) + بطاقة هوية/طلابية اختيارية.
- **مدرّس**: تسجيل بنفس طرق الدخول، بروفايل فيه: صورة شخصية، اسم، هاتف، مدرسة (اختياري)، معهد (اختياري)، محافظة، تخصص، أكتر من مرحلة دراسية ممكنة (اختيار متعدد)، رابط تلغرام، رابط انستغرام، إيميل، إثبات هوية تعليمية (ملف). يبقى الحساب بحالة "قيد المراجعة" لحد ما تقبله الإدارة يدوياً، وعنده خيار إظهار/إخفاء موقعه على الخريطة.
- **إدارة (Admin)**: توافق/ترفض توثيق المدرسين، تضيف/تحذف اختصاصات (مواد) جديدة تظهر بكل مكان بالموقع، تدير لوحة الإعلانات (صور متبدلة تلقائياً) وقسم الأخبار (صورة + تعليق). لازم تكون هاي الشاشة محمية بتسجيل دخول خاص بالإدارة فقط.

## منطق مهم
- **الخريطة مبنية على المحافظة** (مو GPS دقيق) — 18 محافظة عراقية، كل مستخدم يحدد محافظته، والفلترة والبحث يعتمدوا عليها.
- **جلسة أسئلة بمادة واحدة**: الطالب يختار مادة واحدة، يقدر يرسل أكتر من سؤال بنفس المادة ضمن نفس الجلسة، ولما يضغط "إنهاء" يرجع لصفحة اختيار المواد.
- **تعديل المرحلة الدراسية للطالب يمسح أسئلته السابقة** (تنبيه واضح قبل التأكيد).
- **عداد "أجاب على X طالب"**: نقطة خضراء + رقم بجانب اسم المدرّس، تزيد كل ما طالب يأكد إنه استلم رد فعلي.
- **خصوصية الموقع**: المدرّس اللي وافق على الإظهار بيظهر كنقطة صفراء على الخريطة بموقع تقريبي (محافظته)، مع بياناته اللي عبّاها (هاتف، تلغرام، انستغرام) بس عند فتح بطاقته.

## قاعدة البيانات (ERD مبدئي)
```
USERS (id, login_method, email, phone, age_confirmed)
TEACHER_PROFILES (id, user_id FK, full_name, school, institute, governorate,
  stages[] (متعدد), telegram_url, instagram_url, photo_url,
  location_visible, verification_status, id_document_url, answered_count)
SUBJECTS_TAUGHT (id, teacher_id FK, subject_name)  -- المواد قابلة للإضافة من لوحة الإدارة
QUESTIONS (id, student_id FK, subject_name, question_text, status, created_at)
NOTIFICATIONS (id, question_id FK, teacher_id FK, status, sent_at)
MESSAGES (id, question_id FK, sender_id FK, body, sent_at)
STUDENT_PROFILES (id, user_id FK, full_name, phone, governorate, stage, id_document_url)
ADS (id, image_url, caption, order, active)
NEWS (id, image_url, caption, created_at)
```

## التقنية المقترحة للـ MVP
- **Frontend**: Next.js (React) — يقدر يعيد استخدام منطق `prototype/index.html` كنقطة بداية.
- **Backend + قاعدة بيانات + تخزين ملفات + Auth**: Supabase (Postgres + Auth + Storage جاهزين، أسرع من بناء Backend من الصفر لمرحلة الـ MVP).
- **الخريطة**: OpenStreetMap + Leaflet (مجاني) بدل الرسم التوضيحي.
- **الإشعارات**: البداية بإيميل (Supabase + Resend/SendGrid)، لاحقاً Push Notifications.
- **الاستضافة**: Vercel للـ Frontend، Supabase Cloud للـ Backend.

## أولوية البناء (اقترحها بالترتيب)
1. مخطط قاعدة البيانات فعلياً بـ Supabase + Auth (بريد/هاتف).
2. تسجيل الطالب والمدرّس (بما فيهم رفع الملفات: صورة، إثبات هوية).
3. شاشة إدارة بسيطة لقبول/رفض توثيق المدرسين + إدارة الاختصاصات.
4. الخريطة الحقيقية (Leaflet) + فلترة محافظة/مادة.
5. تدفق الأسئلة + الإشعارات + الرسائل الداخلية.
6. لوحة الإعلانات والأخبار (تُدار من الإدارة).

## ملاحظة أمان
لوحة تحكم الإدارة يجب أن تكون خلف تسجيل دخول ودور (role) خاص من أول يوم — ما تبنى كصفحة عامة الوصول أبداً حتى بمرحلة التطوير.
