# الدليل التقني لمنصّة «دليلي»

🌐 **English version:** [`TECHNICAL_GUIDE.en.md`](./TECHNICAL_GUIDE.en.md)

توثيق تفصيلي لبنية المشروع وكل الميزات التي بُنيت، لتسهيل الفهم والصيانة والتطوير لاحقاً.

> ملاحظة: هذا الملف مرجعٌ عام. الشرح الدقيق لكل سطر موجود كتعليقات عربية داخل الملفات نفسها (مكوّنات الواجهة، الأفعال، ملفات الـ migrations).

---

## ١) نظرة عامة

«دليلي» منصّة عراقية (عربية، RTL) تربط الطلاب بمدرّسين موثّقين حسب **المحافظة والمادة والمرحلة الدراسية**. الواجهة الرئيسية **خريطة تفاعلية** تعرض المدرّسين، مع نظام **أسئلة/رسائل** و**تقييمات** و**إشعارات فورية**.

### التقنيات
| الطبقة | التقنية |
|---|---|
| الواجهة | Next.js 15 (App Router) + TypeScript + Tailwind |
| الخادم/القاعدة | Supabase (Postgres 16 + Auth + Storage + RLS) |
| الخريطة | Leaflet + react-leaflet + react-leaflet-cluster |
| الإشعارات | Web Push (VAPID) عبر Database Webhook + مسار API |
| الاستضافة | Vercel (الواجهة) + Supabase Cloud (الخلفية) |
| PWA | manifest + service worker (sw.js) |

### مبادئ أساسية
- **الأمان الحقيقي في القاعدة (RLS):** كل الحمايات مفروضة على مستوى Postgres؛ الواجهة طبقة ثانية فقط.
- **المفتاح الخدمي `service_role` خادمي فقط** (متغيّر بيئة، لا يُرسل للعميل أبداً، لا يُرفع للمستودع).
- **الهجرات (migrations) تُطبَّق يدوياً** عبر Supabase SQL Editor، وكلها **idempotent** (آمنة لإعادة اللصق).

## ٢) بنية قاعدة البيانات

### الجداول الأساسية
- `teacher_profiles` / `student_profiles` — ملفات المستخدمين (مرتبطة بـ `auth.users`).
- `governorates` (18 محافظة بإحداثيات) · `subjects` · `stages`.
- `teacher_subjects` / `teacher_stages` — علاقات متعدّدة.
- `questions` / `messages` / `notifications` — تدفّق الأسئلة والمحادثة.
- `teacher_ratings` — التقييمات.
- `reports` — البلاغات.
- `account_status` — حالة الحساب (تعطيل ذاتي + حظر إداري).
- `announcements` — التبليغات والإعلانات.
- `push_subscriptions` — اشتراكات الإشعارات الفورية لكل جهاز.
- `user_roles` — الأدوار (admin).
- `app_config` — إعدادات (URL/سرّ الـ webhook) تُقرأ فقط عبر دوال SECURITY DEFINER.

### `teacher_directory` (منظور/VIEW عام بلا PII)
منظورٌ يملكه النظام (definer view) يعرض **الأعمدة العامة فقط** للمدرّسين المقبولين النشطين (يستثني: غير المقبول، المعطّل ذاتياً، المحظور). لا يحوي الهاتف/الإيميل (منع سحب البيانات). الدوال `map_teachers()` و`search_teachers()` تقرأ منه.

## ٣) نظام الأمان (ملخّص الحمايات)

| الحماية | الآلية |
|---|---|
| منع المدرّس من توثيق نفسه | تريغر `clamp_teacher_insert` يفرض pending/0 لأدوار التطبيق |
| منع تسريب PII | `teacher_directory` منظور definer بأعمدة عامة فقط |
| تحديد هوية المستخدم | `auth.uid()` يقرأ claim الـ JWT؛ موثوق داخل SECURITY DEFINER |
| منع تزوير الرسائل/الأسئلة | تريغرات تفرض المُرسِل = الحساب + حدود معدّل |
| منع الحظر/التوثيق المزوّر | سياسات + تريغر `protect_account_ban` |
| SSRF في مسار الدفع | قائمة سماح + التحقّق من سرّ الـ webhook (مقارنة ثابتة الزمن) |

دوال تحديد الدور (SECURITY DEFINER، تتجاوز RLS للقراءة): `is_admin()`, `is_teacher()`, `is_student()`, `is_banned()`, `is_account_deactivated()`.

## ٤) الميزات وكيف تعمل

### ٤.١ الخريطة + البحث + الفرز
- `HomeView.tsx`: يحمّل كل المدرّسين (عبر `map_teachers`)، ويفلتر في المتصفح حسب **المادة/الجنس/الاسم**.
- **قائمة فرز منسدلة**: «الأقرب / الأعلى تقييماً / الأنشط». «الأقرب» يحسب المسافة (هافرسين) من محافظة المستخدم المسجّل (تُجلب خادمياً `getUserGov`)، ويُخفى للزائر بلا محافظة.
- التجميع (clustering): الضغط على تجمّع يفتح قائمة ببطاقات المدرّسين فوراً.

### ٤.٢ صفحة المدرّس العامة — `/teacher/[id]`
- تقرأ من `teacher_directory` (تستثني غير الصالح → 404).
- تعرض: الملف الكامل + **المراجعات المكتوبة** (بلا اسم الطالب حفاظاً على الخصوصية) + **عنوان SEO** (`generateMetadata`) + مشاركة واتساب/تلغرام + زر إبلاغ.
- أداء: `getProfile` مغلّف بـ React `cache()` (استعلام واحد لكل طلب بدل مرّتين).
- **قرار أمني:** لا تُعرض بيانات تواصل (هاتف/إيميل) على صفحة يفهرسها Google.

### ٤.٣ التقييمات — `teacher_ratings`
- تقييم واحد لكل (طالب، مدرّس)، مشروط **بتفاعل حقيقي** (المدرّس ردّ على الطالب).
- المتوسّط والعدد يُحسبان **حيّاً** في `teacher_directory` (ينعكس أي تعديل فوراً).
- **إشراف الأدمن** (`/admin/ratings`): بحث بمدرّس → تعديل/حذف أي تقييم (migration 31 يضيف صلاحية UPDATE للأدمن؛ الحذف كان مسموحاً له أصلاً).

### ٤.٤ البلاغات والحظر — `reports` + `account_status.banned`
- **البلاغ** (`ReportButton`): المُبلِّغ يُدرج بلاغه فقط، **لا بلاغ عن النفس**، **لا انتحال**، **بلاغ مفتوح واحد لكل زوج** (فهرس فريد جزئي). الإدارة وحدها تقرأ.
- **الحظر الإداري**: عمود `banned` محمي بتريغر `protect_account_ban` (المحظور لا يفكّ حظر نفسه). المحظور **يختفي من الدليل** و**يُمنع من الرسائل/الأسئلة/التقييم** عبر **سياسات RESTRICTIVE**.
- صفحة `/admin/reports`: مراجعة/تجاهل/حظر.

### ٤.٥ التبليغات والإعلانات — `announcements`
جدول موحّد يخدم ثلاث حالات:
- `audience`: `students` / `teachers` / `all` / `user`.
- `kind`: `announcement` / `tip` / `approval`.

**القراءة (RLS):** كلٌّ يرى حسب دوره (`is_student`/`is_teacher`) أو الموجّه له شخصياً؛ **الأدمن يرى الكل** (للإدارة). الإنشاء/التعديل/الحذف **للأدمن فقط**.

**المسارات:**
- **إشعار توثيق المدرّس**: عند القبول (`setTeacherVerification`) يُدرَج صفّ `audience='user', kind='approval'` → تريغر الدفع يرسله **push** للمدرّس + يظهر كبانر.
- **تبليغ للطلاب/الأساتذة + نصيحة اليوم** (`/admin/announcements`): ثلاث خانات → يصل **push للجمهور + بانر** داخل التطبيق (`AnnouncementsBanner`، قابل للإخفاء بحفظ محلي).

### ٤.٦ الإشعارات الفورية (Web Push) — المعمارية الكاملة
1. المتصفح يشترك (VAPID) → يُخزَّن الاشتراك في `push_subscriptions`.
2. أي إدراج في `notifications` / `messages` / `announcements` يُشغّل تريغر `notify_push_on_insert()` (يقرأ URL/السرّ من `app_config`).
3. التريغر يرسل (عبر `pg_net`) حمولة INSERT إلى مسار `/api/push/send`.
4. المسار (Node runtime): يتحقّق من السرّ، **يعيد جلب الصف من القاعدة** (لا يثق بالحمولة)، يبني نص الإشعار، ثم:
   - **مستخدم واحد** (الأسئلة/الرسائل/التوثيق) → اشتراكاته فقط.
   - **فئة** (طلاب/أساتذة/الجميع) → اشتراكات كل الجمهور المطابق.
5. يرسل عبر `web-push` ويحذف الاشتراكات الميتة (404/410).

> لإضافة قناة دفع جديدة: أضِف تريغر `notify_push_on_insert` على الجدول + فرعاً في `buildTarget` داخل المسار. لا حاجة لإعداد webhook جديد.

### ٤.٧ الوضع الليلي 🌙
- الألوان **متغيّرات CSS** (قنوات RGB) تُعرّف لـ `:root` (نهار) و`:root[data-theme="dark"]` (ليل) — قلب سمة واحدة يبدّل كل الواجهة.
- توكِن `card` (أبيض نهاراً/كحلي ليلاً) بدل `bg-white`.
- زر التبديل في الشريط السفلي + حفظ في `localStorage` + سكربت **no-flash** في `<head>` قبل أول رسم. الافتراضي فاتح.

### ٤.٨ شاشة البداية + PWA
- `#dalili-splash`: شعار دائري + حلقة نابضة + وسم + نقاط تحميل، دخول متدرّج وخروج نظيف (`visibility:hidden`).
- PWA: `manifest.ts` + `sw.js` (الآن يخدم الأيقونات المخزّنة فقط ولا يتدخّل في HTML/JS — يمنع ChunkLoadError).

## ٥) تحسينات الأداء
- **بيانات الرئيسية** مخزّنة مؤقتاً 30 ثانية (`unstable_cache`).
- **Middleware** لا يستدعي Supabase للزوّار (من لا كوكي جلسة `sb-`) — جولة شبكة أقل لكل تنقّل.
- **صفحة المدرّس**: `cache()` يدمج الاستعلام المكرّر.
- الصور عبر `next/image` حيث أمكن + preload للبانر العلوي.

---

## ٦) سير العمل والصيانة
- **التطوير** على فرع `claude/database-architecture-explanation-*`، ويُدمج إلى `main` بالدمج السريع عند طلب «حدّث main».
- **الهجرات يدوية**: الصق ملف `supabase/migrations/*.sql` في Supabase SQL Editor. كلها idempotent.
- **متغيّرات البيئة (Vercel):** `NEXT_PUBLIC_SUPABASE_URL`, `NEXT_PUBLIC_SUPABASE_ANON_KEY`, `SUPABASE_SERVICE_ROLE_KEY` (خادمي)، مفاتيح VAPID (`NEXT_PUBLIC_VAPID_PUBLIC_KEY`, `VAPID_PRIVATE_KEY`, `VAPID_SUBJECT`)، و`PUSH_WEBHOOK_SECRET`.
- **إعدادات الـ webhook** تُخزَّن في `app_config` (المفاتيح: `push_webhook_url`, `push_webhook_secret`).

### قاعدة برمجية مهمّة (درس مستفاد)
ملفات `"use server"` **لا يجوز أن تُصدّر إلا دوالّ async**. تصدير ثابت (const) منها يصل **معطوباً** إلى العميل ويسبّب انهياراً وقت التشغيل. الثوابت/الأنواع المشتركة توضع في ملف عادي (مثل `lib/reports/constants.ts`).
